### 2.1 真實翻譯執行快照（A｜2026-08-10）

使用者以自己的 Gemini API Key 執行中，透過 `GET /api/pipeline/status` 取得（已移除 `caption.text`，
本報告不記錄任何逐字稿內容）：

```text
running          : true
elapsed_seconds  : 160.97
status_revision  : 38
audio_source     : running
gemini_provider  : connected   (generation=1)
gemini_session   : active      (generation=1 rotation_seconds=480.0)
caption          : revision=241  status=partial  language_code=zh-Hant  session_generation=4
meter            : rms -7.57 dBFS / peak -0.31 dBFS / clipping=false
last_error       : null
```

判讀：連續執行 2 分 41 秒無錯誤，字幕更新 241 次且語言為 `zh-Hant`，音訊持續有訊號，
Gemini session 尚未達到 480 秒輪替點。

**同一份快照揭露的缺陷**：`caption_sink` 當時顯示 `idle`／`revision=0`，但字幕已更新 241 次。
原因是字幕狀態的發布只實作在 CLI 路徑，`PipelineRuntime` 未發布，導致控制頁的「字幕輸出」
永遠停在 idle。已修正並補上回歸測試（共用 `backend/app/status/caption_status.py`，
CLI 與 API runtime 使用同一份對映）。

**觀察（非缺陷）**：`caption.session_generation`（4）與 `gemini_session.session_generation`（1）
語意不同——前者跨多次 Start 累計，後者為單次執行內的計數。Stage 3.1／Stage 4.1 觸及 UI 時
應統一命名或明確標示，避免誤讀。

**操作建議**：peak −0.31 dBFS 過熱，建議來源音量下修 3–6 dB，破音會直接降低辨識準確度。

## 4. 安全邊界實測（A）

- **只綁 `127.0.0.1`**：`--host 0.0.0.0` 直接 exit 1 且不啟動 server；`features.lan_access` 不放行。
- **無 CORS middleware**：有測試守住，避免任何網頁驅動本機 pipeline。
- **WebSocket Origin 白名單**：只接受 loopback 來源，其他以 1008 關閉。瀏覽器不對 WebSocket
  套用同源政策，沒有這道檢查等於任何網站都能讀取字幕。
- **字幕只用 text node**：掃描整個 `src` 確認無 `dangerouslySetInnerHTML`／`.innerHTML =`；
  含 `<script>` 的字幕顯示為純文字。
- **Overlay 樣式參數 fail closed**：顏色只接受嚴格 `#RRGGBB`、字型走白名單，注入嘗試回預設值。
- **逐字稿不落地**：無檔案輸出路徑；本報告不含任何逐字稿內容。

## 6. 已知限制（非缺陷）

- ~~字幕為單一持續累積的長句，只提供視覺行數~~ → **Stage 3.1 已解除**：後端排版器以
  「每行字數 × 行數」產生 `CaptionState.lines`，控制頁可於翻譯進行中即時調整。
  `caption.max_payload_length`（預設 4096 字元）仍限制後端保留多少累積文字；
  **捲動的是視覺視窗，不是後端狀態**。
- Gemini Live 在連續語音下幾乎不送 `finished=true`，字幕多數時間維持 `partial`；
  句尾標點收束規則留待 Stage 3.1。
- 開發模式下 WebSocket 直連後端（不走 Vite proxy），因 Vite 8 的 ws proxy 在此環境會於
  upgrade 階段丟 `write ECONNABORTED`。正式 build 由後端提供，屆時同源。
